# Layout responsive ultra-wide

- Usare griglie fluide e breakpoint guidati dal contenuto, non una serie di larghezze fisse: MDN indica CSS Grid e Flexbox come strumenti responsive e sconsiglia pagine a larghezza fissa, che creano spazio vuoto sui monitor grandi e scroll sui dispositivi stretti. [MDN — Responsive web design](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Responsive_Design)
- Limitare la larghezza delle colonne editoriali anche su schermi ultra-wide: MDN segnala che righe troppo lunghe diventano difficili da leggere e suggerisce colonne più strette. Le card possono quindi espandere il layout senza lasciare crescere indefinitamente il testo. [MDN — Responsive web design](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Responsive_Design)
- Evitare overflow orizzontale per il contenuto leggibile: WCAG 2.2 richiede il reflow senza perdita di informazione e senza scroll in due dimensioni fino a 320 CSS px, salvo contenuti che richiedono davvero una superficie bidimensionale. [W3C — Understanding SC 1.4.10 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- Gestire URL, nomi di testata o stringhe senza spazi con `overflow-wrap`, così una card non forza la pagina oltre il viewport. MDN documenta `overflow-wrap: anywhere`/`break-word` per prevenire l’overflow; W3C raccomanda inoltre link con testo leggibile invece di URL mostrati per esteso. [MDN — overflow-wrap](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow-wrap) · [W3C — Technique C33](https://www.w3.org/WAI/WCAG22/Techniques/css/C33)
- Per card editoriali in una sezione orizzontale, ogni singola card deve restare completamente leggibile senza un secondo scroll orizzontale interno; W3C indica 320 CSS px come riferimento per i pannelli su pagine a scorrimento verticale. [W3C — Technique G225](https://www.w3.org/WAI/WCAG22/Techniques/general/G225)
